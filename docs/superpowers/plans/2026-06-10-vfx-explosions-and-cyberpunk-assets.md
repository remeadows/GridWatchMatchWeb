# Board VFX Overhaul: Explosions, Power-Up Choreography, Win Sequence, Asset Contrast

> **For agentic workers:** Execute task by task. Each task has TDD steps (write failing test → run → implement → run → commit). Do not skip tests. Do not batch commits. After each task run `bash cli/codex-gate.sh` and fix findings until clean before moving on. If anything fails or is ambiguous, stop and ask.

**Goal:** The board animates correctly but reads as lifeless, and two genuine bugs make power-ups feel broken. This plan (a) fixes the bugs, (b) rebuilds the match pop and all four power-up effects as choreographed VFX with particles, projectiles, and camera shake, (c) adds the iOS-parity bottom-to-top board destruction on level win, and (d) raises tile/asset contrast so the five tile types stop blending into each other and into the board. Engine logic, level JSON, and match rules do not change.

**Reference (do not import or modify):** iOS `BoardNode.swift` — `animateClears`, `animateRowDestruction`, power-up effect nodes. `src/game/motion.ts` JSDoc already cites these.

## Confirmed Bugs (fix first — they are why power-ups feel dead)

1. **Booster/tap power-up clears never pop.** `BoardScene.playResolvedAnimation` (non-swap branch, `src/game/BoardScene.ts:374-381`) calls `buildPostClearSnapshot(baseline, new Set())` with an **empty** popped set even when `delta.clears` is non-empty. The comment "for tap/booster paths there were no clears in this delta tick" is wrong for TNT/rocket/propeller/lightBall taps. Result: tiles destroyed by a tapped power-up stay frozen on the board during the cascade, then blink out of existence on the final `renderSnapshot`. There is no destruction animation at all on this path.
2. **Power-up FX render after the destruction is over.** `playDeltaEffects` is invoked inside the cascade's `onComplete` (`src/game/BoardScene.ts:378-381` and `:391-394`), so the TNT circle / rocket line fades in *after* the cleared tiles are gone and replacement tiles have already fallen. The explosion happens after the corpse is buried.
3. **`playPowerUpEffect` is a static drawing, not an effect** (`src/game/BoardScene.ts:716-754`). One `Graphics` shape per event, alpha-faded over 560 ms: a pre-drawn full-length line for rockets (nothing travels), a stroked circle for TNT (no blast), static spokes for the propeller (the drone never flies), a circle+rect for lightBall. No particles, no projectile motion, no impact timing.
4. **No win sequence.** `finishWin` (`src/App.tsx:334-347`) sets `status = "won"` synchronously and the `ResultModal` (`src/App.tsx:666`) covers the board immediately. iOS plays `animateRowDestruction` — rows explode bottom-to-top — before the result UI. `seededAngleJitter` in `motion.ts` was built for exactly this and nothing uses it for a win.
5. **Minor:** in `playTilePops` the `flashCell` ring fires immediately for every popped tile while the pop tween itself is centroid-staggered, so the flash and the pop are desynchronized. Minor: `RESOLVE_ANIMATION_BUDGET_MS` does not include `powerUpEffect` duration, so queued actions can re-render over in-flight power-up FX (`renderSnapshot` clears the fx layer).

## Asset findings (why everything blends)

- All five tiles (`public/assets/images/tiles/`) share the same dark hexagon + circuit-board motif at nearly the same value and saturation, on a dark navy board (`0x071420` board, `0x10283b` cells). Silhouettes are identical; only the inner glyph differs. At gameplay size the glyph glow is the only signal, and threat (red) vs firewall (orange), packet (blue) vs zeroDay (white-blue) sit in adjacent hue bands.
- `powerup_tnt.png` is a cartoon wooden crate (Crash Bandicoot style) — a hard style mismatch with the holographic tiles. The user wants **realistic cyberpunk**, not cartoon.
- **Pipeline caveat:** `npm run sync:assets` (`scripts/sync-ios-assets.mjs`) copies assets from the iOS repo and will clobber any replaced web PNGs. MEMORY.md forbids modifying the iOS repo. Any web-specific art must live behind an override mechanism (Task 8).
- An agent cannot author production raster art. Task 8 therefore does three things it *can* do: renderer-side contrast/glow coding per tile type, a sync-safe override directory, and a committed art-direction spec + generation prompts so the user can drop in final art with zero code changes.

**Hard constraints (AGENTS.md / MEMORY.md):**
- `src/engine` stays pure: no Phaser/DOM/React imports there. None of these tasks touch the engine.
- Respect `reducedMotion` on every new effect: skip straight to the end state.
- Keep the action queue max depth 3 and keep `RESOLVE_ANIMATION_BUDGET_MS` derived from the timing constants.
- Test-only globals stay gated behind `?gwTestMode=1`.
- Do not commit new binary assets generated by the agent; art comes from the user via Task 8's spec.
- Keep `npm run test`, `npm run test:e2e`, `npm run validate:levels`, `npm run build` green after every task.
- The e2e drag test is flake-prone: before declaring this plan done, run the 20-iteration loop documented in `HANDOFF.md` against a warm preview server.
